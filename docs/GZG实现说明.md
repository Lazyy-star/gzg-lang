# GZG 解释器实现说明

解释器约 7800 行 C99 代码，无第三方依赖。整体是经典的“单遍编译 + 字节码虚拟机”结构，设计参考了 Lua 与《Crafting Interpreters》中的 clox，并在此基础上增加了整数/浮点分离、结构体、命名参数、模式匹配、异常处理、字符串插值、中英双语关键字等特性。

```
源码 ──lexer.c──▶ 记号流 ──compiler.c──▶ 字节码(chunk.c) ──vm.c──▶ 执行
                                                       │
                              memory.c（标记-清除 GC） ◀┘   builtins.c（内建函数） platform.c（系统接口）
```

| 文件 | 行数 | 职责 |
|---|---:|---|
| `lexer.c` | ~380 | 词法分析：双语关键字表、插值字符串状态机、自动分号、全角符号检测 |
| `compiler.c` | ~1700 | Pratt 表达式解析 + 递归下降语句解析，直接生成字节码；作用域与闭包解析 |
| `chunk.c` | ~210 | 字节码容器、常量池、反汇编器（`--dis`） |
| `vm.c` | ~1700 | 指令分派、调用约定、异常处理、字符串化、错误提示 |
| `object.c` / `table.c` / `value.c` | ~600 | 对象分配、字符串驻留、有序字典、哈希表、值比较与浮点格式化 |
| `memory.c` | ~230 | 标记-清除垃圾回收 |
| `builtins.c` | ~1800 | 约 60 个全局函数和约 80 个内建方法 |
| `platform.c` | ~400 | Windows 宽字符路径、UTF-8 控制台、进程、目录、计时 |

## 1. 值的表示

`Value` 是 16 字节的带标签联合体：`nil / bool / int(int64) / float(double) / obj(指针)`。整数和浮点数分开存储，因此 `7 // 2` 能得到精确的整数，整数运算走单独的快速路径。另有一个用户不可见的 `UNDEF` 标签，表示“未定义的全局变量”和“调用时未传入的参数”。

堆对象有 11 种：字符串、函数原型、闭包、upvalue、原生函数、数组、有序字典、结构体类型、结构体实例、绑定方法、区间。

- **字符串**全部驻留（intern）：相同内容只存一份，字符串相等比较退化为指针比较，字典查找也因此很快。对象里同时记录字节数和码点数，纯 ASCII 字符串下标是 O(1)。
- **字典**是有序哈希表：条目按插入顺序存放在数组里，另有一个开放寻址的索引数组指向条目。删除留下墓碑，条目区满时若墓碑较多则原地压缩。这与 CPython 3.7+ 的 dict 结构相同。
- **结构体实例**的字段是定长数组，字段名到下标的映射存在结构体类型上，所以实例很小，访问不存在的字段能立即报错。

## 2. 词法分析

- **自动分号**：仿照 Go 的规则，换行前的记号能结束表达式时产生 `NEWLINE` 记号。词法分析器维护一个括号栈，在 `(`/`[` 内忽略换行，在 `{` 内保留，因此 `f(a,\n b)` 可以折行，而 `{ }` 代码块中的换行仍然分隔语句。
- **链式续行**：遇到换行时向前看下一个非空行，以 `.标识符` 或 `|>` 开头就不产生 `NEWLINE`。
- **字符串插值**：扫描到字符串里的 `{` 时返回 `INTERP` 片段，并在括号栈压入特殊标记 `i`；之后正常扫描表达式，遇到与之匹配的 `}` 时回到字符串扫描。因为用的是同一个栈，插值可以任意嵌套（`"{"{x}"}"`）。
- **双语关键字**：关键字表里每个记号类型有英文、中文两个条目，编译器只看记号类型，二者生成的字节码完全相同。

## 3. 编译器

单遍编译：解析的同时生成字节码，不构建 AST。

- **表达式**用 Pratt 解析器，每种记号对应 `(前缀函数, 中缀函数, 优先级)`。18 级优先级中 `**` 右结合、比一元负号高，`not` 比比较运算低（与 Python 一致）。
- **变量解析**在编译期完成：局部变量编译为栈槽下标（`GET_LOCAL n`），外层函数的变量编译为 upvalue 下标，其余视为全局变量，编译为全局表下标（`GET_GLOBAL n`）。运行时不需要按名字查找任何变量。
- **闭包**：被内层函数捕获的局部变量会变成 upvalue。变量离开作用域时，若被捕获则执行 `CLOSE_UPVALUE`，把值从栈上搬到堆上的 upvalue 对象里。`for` 循环每一轮都会关闭循环变量，所以每轮的闭包捕获的是不同的变量。
- **数值 for 循环**编译成三条专用指令：`FOR_PREP` 校验边界并把闭区间转为开区间，`FOR_RANGE` 检查是否结束并压入循环变量，`FOR_STEP` 自增后跳回。循环计数器、终点、步长放在三个隐藏的局部变量里，不创建区间对象。
- **默认参数**：函数开头为每个有默认值的参数生成 `JUMP_IF_NOT_UNDEF 槽位` + 默认值表达式，调用者没传的参数以 `UNDEF` 填充，所以默认值在每次调用时求值。
- **match**：subject 求值后留在栈顶；每个模式 `DUP` 后比较，命中则跳到分支体。分支体执行前先弹出 subject，所以分支体内声明的局部变量槽位与正常代码一致。绑定模式直接把栈顶的 subject 当作新的局部变量。
- **try/catch**：`TRY 偏移` 登记处理器；块正常结束时 `END_TRY` 注销；catch 块开头栈上是异常值，编译器把它声明为局部变量 `e`。`break`/`continue`/`return` 跳出 try 块时编译器会补上相应数量的 `END_TRY`。

## 4. 虚拟机

- **指令分派**：GCC 下使用“标签地址”（computed goto），每条指令末尾直接跳转到下一条指令的处理代码，比 `switch` 少一次边界检查和间接跳转，分支预测也更好。
- **调用约定**：被调函数及其参数已经在栈上，新调用帧的 `slots` 指向被调函数所在的栈槽，参数就是前几个局部变量，调用不需要复制参数。`OP_CALL` 对“闭包 + 参数个数正好匹配”的最常见情形走内联的快速路径。
- **方法调用**：`obj.m(args)` 编译为 `INVOKE 名字 参数个数`，直接在结构体的方法表里查找并调用，不创建绑定方法对象；`obj.m` 单独取值时才创建绑定方法。
- **命名参数**：`CALL_KW` 携带一个常量“参数名数组”，虚拟机按函数的形参名把实参重排后再调用。
- **异常**：处理器栈记录 `(调用深度, 栈顶, catch 地址)`。抛出时取最近的处理器，关闭将被丢弃的 upvalue，恢复调用深度和栈顶，压入异常值，跳到 catch。原生函数（如 `map`）回调 GZG 函数时会递归进入 `run()`，异常若属于外层则先退出内层 `run()`，由外层继续处理，因此异常可以穿过任意层回调。
- **错误提示**：未定义的变量、字段、方法、参数名会与当前可见的名字计算编辑距离给出建议；另有一张“其他语言写法 → GZG 写法”的对照表（`append→push`、`None→nil` 等），专门照顾习惯了 Python/JS 的用户和 AI。

## 5. 垃圾回收

三色标记-清除：

1. **标记根**：值栈、调用帧中的闭包、开放的 upvalue、全局变量表、内建方法表、编译器正在构造的函数、临时根。
2. **追踪**：灰色对象出栈并标记它引用的对象。字符串、区间、原生函数是叶子对象，标记后不入灰栈。
3. **清理驻留表**：字符串驻留表是弱引用，未标记的字符串先从表中删除。
4. **清扫**：遍历所有对象的链表，释放未标记的对象。

触发条件是已分配字节数超过阈值，回收后阈值设为存活字节数的 2 倍（最小 8MB）。

**GC 正确性**的关键是“新分配的对象在下一次分配之前必须可达”。代码中凡是连续分配的地方都先把对象 `push` 到值栈上。`make stress` 用 `-DGC_STRESS` 编译，使每一次分配都触发完整的 GC，用它跑完整测试集，能暴露几乎所有漏掉的根。

## 6. 平台适配

Windows 下命令行参数和文件路径来自系统的 UTF-16 接口，统一转成 UTF-8 后在解释器内部使用，再在 `_wfopen` 等调用前转回 UTF-16，因此中文路径、中文参数都能正常工作。启动时把控制台代码页设为 UTF-8 并开启 ANSI 转义处理，`print` 中文和彩色输出不会乱码。

## 7. 可观察性

| 选项 | 作用 |
|---|---|
| `--dis` | 反汇编每个函数的字节码，显示行号、操作数、跳转目标 |
| `--tokens` | 显示词法记号及其行列 |
| `--stats` | 运行结束后显示总耗时、GC 次数与耗时、累计分配量、堆峰值 |
| `-DTRACE_EXEC` 编译 | 打印每条指令执行前的栈内容 |

示例：`fib.gzg` 反汇编后的字节码（行号列中 `|` 表示与上一条指令同一行）：

```gzg
fn fib(n) {
    if n < 2 { return n }
    return fib(n - 1) + fib(n - 2)
}
print(fib(30))
```
