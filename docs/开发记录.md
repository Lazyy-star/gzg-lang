# 项目开发记录（编程 Agent 辅助开发全过程）

本项目全程在 Claude Code（模型 Claude Opus）中完成。主 Agent 负责设计与核心实现，并按任务派生了 3 个子 Agent。下表的时间与 `git log` 一致。2048 应用的逐步开发记录见 [apps/game2048/DEVLOG.md](../apps/game2048/DEVLOG.md)。

## 1. 分工

| 角色 | 输入（它能看到什么） | 产出 |
|---|---|---|
| 主 Agent | 作业要求 | 语言设计、头文件接口、词法/编译器/虚拟机/GC、文档、性能用例、PPT，以及根据其他 Agent 反馈所做的修复 |
| 子 Agent A：内建函数库 | 头文件与一份接口约定（GC 规则、报错约定、函数清单） | `builtins.c`、`platform.c`（约 2200 行） |
| 子 Agent B：黑盒测试 | **只有**语法文档和 Skill 文档，禁止阅读 `src/` | 321 个测试，以及 12 条“实现与文档不一致”的报告 |
| 子 Agent C：应用开发 | **只有** `.claude/skills/gzg/` 下的三份文档，禁止阅读源码、测试和其他文档 | 2048 + AI（925 行），以及自己的开发记录 DEVLOG.md |

B 和 C 被刻意限制了可见范围：B 只看文档，所以它发现的问题就是“文档与实现不一致”；C 只看 Skill，所以它踩到的坑就是“给 AI 的文档还缺什么”。

## 3. 关键决策与理由

- **实现语言选 C 而不是 Python。** 作业允许任何实现语言；用 Python 写的树遍历解释器通常比 CPython 慢 50~100 倍，性能对比就没有意义。用 C 写字节码 VM，才能讨论“为什么快、为什么慢”。
- **单遍编译 + 字节码，而不是 AST 解释。** 变量在编译期解析为栈槽/全局下标，是性能领先的主要原因；同时 `--dis` 能直接展示编译结果，便于答辩讲解。
- **测试由“只看文档”的 Agent 编写。** 如果实现者自己写测试，测试会默认实现是对的。B 发现的 12 处不一致里，有 3 处是会让进程卡死或崩溃的真 bug。
- **应用由“只看 Skill”的 Agent 编写。** 这是检验“给 AI 的文档是否足够”的唯一可信办法。C 全程只报错 2 次，并准确指出了文档缺失的 4 处，这些都已补上。
- **不为 `strings` 用例继续优化。** 根因是追踪式 GC 不知道引用计数，无法像 CPython 那样原地追加；要解决需要分代 GC 或专门的字符串构建器。由于已有线性时间的 `push` + `join` 写法，选择在文档中推荐它，而不是增加实现复杂度。

## 4. 子 Agent 发现、由主 Agent 修复的问题汇总

| # | 发现者 | 问题 | 修复 |
|---|---|---|---|
| 1 | B | 结构体字段默认值写错时编译器死循环 | 出错后跳到下一个成员；后来还连带导致了 C 的卡住 |
| 2 | B | `map` 回调中递归约 2270 层时 C 栈溢出、无任何输出地崩溃 | 链接 64MB 栈；原生回调嵌套上限 20000，超出时抛出可捕获错误 |
| 3 | B | `to_str()` 递归 5000 层同样崩溃 | 同上 |
| 4 | B | 嵌套超过 200 层的相同结构 `==` 返回 false | 上限提高到 100000 |
| 5 | B | 打印超过 64 层被截断成与循环引用相同的 `[...]` | 上限 4096，超限显示 `<嵌套过深>` |
| 6 | B | `map.b` 缺键时报“没有方法 'b'” | 报“字典中没有键 "b"” |
| 7 | B | 换位（`nmae`）、局部变量拼错没有建议 | Damerau 编辑距离；编译期记录局部变量候选 |
| 8 | B | 规范中 `-9223372036854775808` 示例无法编译 | 一元负号后允许 2^63 |
| 9 | B | 规范示例用了不存在的 `divmod` | 改文档 |
| 10 | B | `..=INT_MAX` 被当作空区间 | **未修复**，写入“已知限制” |
| 11 | C | 文档没写 `import`、文件路径基准、全局赋值规则 | Skill 规则 16、17、3 |
| 12 | C | `a if c else b` 报错不清楚且有连带错误 | 编译器专门提示并跳过本行 |
| 13 | 主 | 两个运行器同时写同一个 stderr 临时文件导致全部失败 | 每次运行使用独立的临时文件 |

## 5. 如何复现每一项结论

```bash
mingw32-make                                   # 编译
build/gzg tests/run_tests.gzg                  # 327 个测试
mingw32-make stress                            # GC 压力模式下的测试
mingw32-make coverage                          # 行覆盖率
build/gzg bench/run_bench.gzg                  # 性能对比（驱动用 GZG 编写）
build/gzg apps/game2048/test_board.gzg         # 2048 单元测试
build/gzg apps/game2048/main.gzg --seed 1 --plain < apps/game2048/moves.txt   # 重放一局
```
