## 1. 用 -e / 小文件试验（15:35–15:45）

全部是文档里没有、只能靠试验确认的东西：

| 试验 | 结果 |
|---|---|
| `import "lib.gzg"` | 可用。被导入文件的顶层函数、`const`、`struct` 直接进入全局，不需要前缀 |
| `import lib`（Python 风格） | 语法错误：`import 后面需要文件路径字符串（在 'lib' 处）`（这是我故意试的，不计入开发报错） |
| `import "lib.gzg" as L` | 语法错误：`语句后面多了内容`——不支持别名 |
| `import "lib"`（省略扩展名） | 运行错误：`无法导入文件 'lib'（文件不存在或无法读取）`——扩展名不能省 |
| 从别的目录运行 `gzg gz/m1.gzg` | 正常，说明 import 路径**相对于导入方文件**，而不是当前目录 |
| 同一个文件 import 两次 | 不报错，顶层代码似乎只执行一次（菱形依赖 board ← ai ← main 可以放心写） |
| import 绝对路径 | 可用 |
| 字段默认值 `cells = []` | 每个实例各一份，不共享（和 Python 默认参数不同，好事） |
| `seed(1)` 后 `randint`、`random()` | 两次运行序列完全一样，共用一个生成器 |
| `float("inf")`、`INT_MIN`、`1e18` | 都可用，`print(1e18)` 显示 `1e+18` |
| `[0] * 4`、`[1,2] + [3]` | 可用，同 Python |
| `match s { "w", "up", "上" => ... }` 字符串多值匹配 | 可用 |
| 字典字面量里混用 `"上": ...` 和 `up: ...` 键 | 可用 |
| 管道输入为空时 `input()` | 返回 `nil`，符合文档 |
| 性能：100 万次 while 累加 0.03s、100 万次函数调用 0.015s | 比预想快很多（比 CPython 还快），expectimax 深度 3 应该可行 |

## 2. 阶段一：棋盘逻辑 board.gzg（15:45–15:55）

设计：棋盘是长度 16 的一维数组；`LINES` 预先算好四个方向各 4 条“线”的下标序列，这样四个方向共用一个 `slide_row`（向左推挤合并）。
`move_cells` 不修改输入，返回 `[新棋盘, 得分, 是否变化]`，方便 AI 复用。`Game` 结构体封装棋盘、分数、步数、`won` 标志和 `Snapshot` 历史栈（多步撤销）。
行变换结果用字典缓存（键为 `"2,2,0,0"` 这样的字符串），给 AI 提速。

约 230 行。写完后用一个临时脚本 import 它冒烟测试：`slide_row([2,2,2,2])` 得 `[[4, 4, 0, 0], 8]`，`Game.step/undo` 正常。
**这一阶段零报错**——文档的速览和 15 条规则足够写出这种纯逻辑代码。
